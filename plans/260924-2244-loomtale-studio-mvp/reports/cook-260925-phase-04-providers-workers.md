## Built

**Protos** (`proto/loomtale/worker/v1/{worker,tts,align,train,vision}.proto`): `Worker` control plane (Health/ListEngines/LoadModel/UnloadModel/GpuStatus), `TTS.Synthesize`/`Align.Align`/`Train.Train` server-streaming, `Vision.Score`/`Vision.Depth` unary. Inputs/outputs are presigned URL strings, never raw media; `buf generate` produces Go (`api/internal/workerpb`) and Python (`workers-python/src/loomtale/worker/v1`) stubs from one source.

**Go LLM layer** (`api/internal/providers/llm`): `Provider` interface (`Generate`/`Stream`), `DataBlock`/`RenderDataBlocks` (nonce-fenced `<data-{nonce}>` tags, escapes forged open/close tags inside untrusted text so injected content can never spoof the fence boundary), `ValidateJSON`/`GenerateStructured` (one retry on schema failure) via `santhosh-tekuri/jsonschema/v6`. Adapters: `ollama` (NDJSON `/api/chat`, `/api/generate` load, `/api/ps` residency proof, `keep_alive:0` unload), `anthropic` and `gemini` (direct REST/SSE, not the full SDKs — see Deviations), `claudecli` (calls the sidecar over HTTP, refuses to run when `SaaSMode`).

**registry** (`api/internal/providers/registry`): `Store` (llm_settings table, JSON action-overrides column), `Registry.Resolve`/`QueueFor`/`ModelRefFor` (Ollama → `gpu` queue + `ModelRef`, everything else → `llm` queue, no residency). Designed as a helper phase 6's `StepHandler.Queue`/`ModelRef` delegate to, not a `StepHandler` itself (phase 6 doesn't exist yet).

**llm-cli sidecar** (`api/cmd/llmcli`, new binary): golden argv builder (`argv.go`, locked by a table test), env allowlist (`env.go`: `PATH,HOME,LANG,HTTPS_PROXY,CLAUDE_CODE_OAUTH_TOKEN` only), NDJSON stream-json parser (`ndjson.go`: asserts `system/init` reports empty `tools`/`mcp_servers`, kills the process on violation), process runner (`run.go`: fresh 0700 tmpfs workdir per call, process-group SIGTERM/SIGKILL, `WaitDelay=5s`, weighted semaphore default 2, 64KB scrubbed stderr cap), bearer-token HTTP handler (`handler.go`: `POST /v1/run`, NDJSON relay), startup self-check (`selfcheck.go`: `claude --version` vs pinned version). Go client adapter in `api/internal/providers/llm/claudecli`.

**netguard** (`api/internal/netguard`): allowlist validation at config time plus a `net.Dialer.Control` re-check at actual dial time (blocks 169.254.0.0/16, unspecified, known metadata hostnames; `CheckRedirect` never follows a redirect).

**Python worker** (`workers-python/src/loomtale_worker`): `grpc.aio` server (`server.py`) hosting all five services plus the phase-1 `WorkerHealth`; `BearerTokenInterceptor` (`auth.py`, cardinality-aware — unary and server-streaming both wrapped correctly); `ModelManager` (`model_manager.py`, one `asyncio.Lock`-guarded resident engine, CUDA-OOM string match → `RESOURCE_EXHAUSTED gpu_oom`); `EngineRegistry`/`Engine` protocol (empty until 9a-9c); `gpu.py` (pynvml aggregate VRAM, degrades to `present=False` on any failure — never crashes); `transfer.py` (httpx download/upload, hard size cap, injectable client for tests); `weights.py` (`assert_safe_weights_path`, safetensors/GGUF only, for 9a-9c loaders to reuse). `HF_HUB_OFFLINE`/`TRANSFORMERS_OFFLINE` asserted at startup — refuses to boot without them.

**ComfyUI client** (`api/internal/providers/image/comfyui`): `Submit`/`History`/`FetchOutput`/`ViewURL`/`Free`/`SystemStats`, `ApplyOverrides` (node-id/input-key parameter map over a loaded workflow template, non-mutating). `Backend.Load` returns `ErrEngineNotInstalled` (wrapping `pipeline.ErrEngineNotInstalled`) until phase 9a — no fake workflow execution.

**Residency manager** (`api/internal/providers/residency`): `NvidiaSMIProbe` (aggregate `nvidia-smi --query-gpu`, never per-process; `no_gpu` handled by returning a zero snapshot, never erroring), `Manager` implementing `pipeline.ModelResidency`+`pipeline.GpuProbe` (`Ensure`: unload-all → poll probe every 500ms/512MB headroom until budget confirmed or 60s timeout → load → poll `Resident()` until the backend's own status agrees). `NewManagerWithBudget` measures `budget_mb = free - render_reserve_mb` once at boot. Backend adapters: `ollama.Backend` (real), `comfyui.Backend` (real `Unload`, honest not-installed `Load`), `pyworker.Backend` (fully real against the generic control-plane RPCs).

**gRPC clients for phase 6/7/9c** (`api/internal/providers/{tts,align,train,vision,pyworker}`, shared dial/error-translation in `api/internal/providers/workerconn`): stream progress/log callbacks, `FAILED_PRECONDITION`→`pipeline.ErrEngineNotInstalled`, `RESOURCE_EXHAUSTED`→`pipeline.ErrGPUOOM` so a future `StepHandler.Run` can hand the error straight to `pipeline.Classify`.

**llm_settings + AC8** (`db/migrations/20260925040000_llm_settings.sql`, `db/queries/llm_settings.sql`, `openapi/{paths/settings_llm.yaml,schemas/providers.yaml}`, `api/internal/settingsapi`): `GET/PUT /settings/llm`, `POST /settings/llm/test` (runs an 8-max-token fixed prompt, never tenant content, reports `ok`/`detail` without ever returning a key). `PutLLMSettings` rejects an unconfigured provider name (400) before writing, so a bad override can't silently break the next enqueue.

**Dockerfiles/compose**: `deploy/docker/{pyworker,llmcli,egress-proxy}.Dockerfile`, `deploy/egress-proxy/{tinyproxy.conf,allowed-hosts.conf}`. `compose.yml` gained `llm-cli`, `egress-proxy`, `loomtale_llm` (internal) + `loomtale_egress` (egress-proxy's only outbound leg) networks, and new secrets (`claude_oauth_token`, `llmcli_bearer_token`, `pyworker_bearer_token`). `compose.gpu.yml` gained `ollama` (required, no profile) and `pyworker`, renamed the phase-1b `loomtale_comfyui` network to `loomtale_gpu` (now holds comfyui+ollama+pyworker, worker joins it too — per the plan's progress note "worker joins the comfyui network"). `scripts/dev-secrets-init.sh` generates the two new random shared secrets and an empty `claude_oauth_token.txt` placeholder with an instruction to run `claude setup-token`.

## Deviations from the literal spec text

1. **anthropic-api/gemini-api adapters use direct REST+SSE, not `anthropic-sdk-go`/`google.golang.org/genai`.** I could not iterate against the real SDKs' exact current Go APIs without a live round trip I don't have in this sandbox, and pulling in either SDK's full transitive surface for a ~150-line adapter felt like the wrong trade under KISS. The REST contracts (`POST /v1/messages`, `POST /v1beta/models/{m}:streamGenerateContent?alt=sse`) are the same stable public surface those SDKs wrap. If the team wants the official SDKs specifically (e.g. for future tool-use/vision features neither adapter needs today), swapping the transport inside `anthropic.Provider`/`gemini.Provider` is a contained change — the `llm.Provider` interface and every caller are unaffected.
2. **Per-tenant BYOK for anthropic-api/gemini-api is not implemented.** `registry.Registry.Providers` is a single process-wide map built once at boot from env/secret-file config (`cmd/api/providers.go`); there's no per-tenant key lookup against the phase-2 `secrets` table yet. `settingsapi.SecretsChecker` is wired as an interface specifically so phase 6+ can add that (secret-backed, tenant-scoped provider construction) without touching the HTTP layer again. Ollama and claude-cli are inherently not per-tenant (shared local backend, shared sidecar), so this gap only affects anthropic-api/gemini-api, and only in a multi-tenant deployment — today's owning tenant already gets a working claude-cli default.
3. **`cmd/api`/`cmd/worker` wiring touched beyond the letter of "phase 4 exports constructors, the lead wires at merge."** Both files had an explicit phase-4 handoff point already written in by phase 3 (`Probe: nil, // wired by phase 4`, `Residency: nil, // wired by phase 4`, and the `residency := pipeline.NoopResidency{}` line with `// Phase 4 replaces this`). Leaving those unwired would have left the build broken (`gen.StrictServerInterface` requires every settings method once the openapi paths exist; `NewGPUExecutor` needs a real `ModelResidency` for `WORKER_GPU=true` to mean anything). I only touched those exact spots plus the minimal registry/residency construction they need, verified live against real hardware.
4. **`api/cmd/api`'s `GpuProbe`/`ModelResidency` stay `nil`.** Tracing the network topology (`loomtale_gpu` is `internal: true`, only `worker` joins it) showed `cmd/api` has no route to comfyui/ollama/pyworker at all — a real probe there would either always report `no_gpu` or require punching a hole in the isolation the plan explicitly asked for. `pipelineapi.GetGpuStatus` already treats a nil `Probe`/`Residency` as "omit those fields," so `/gpu` still works, just without live VRAM data from the api process; a real live view needs the worker to expose status over `loomtale_core` (out of phase 4's scope, flagged as a question below).
5. **`workers-python/src/loomtale_worker/health_server.py` (phase 1) is untouched.** `server.py` wraps its sync `WorkerHealthServicer.Check` in a tiny async adapter rather than converting the phase-1 file to `grpc.aio`, since that file isn't in phase 4's file-ownership list and its existing test still passes unmodified.
6. I did not add a new `.gitignore`/secrets file for anthropic/gemini API keys beyond the existing generic `secrets` table (kind=`llm_api_key`) the spec already names — no compose secret was invented for them, matching point 2 above.

## What the user must do to enable the live Claude path

1. Run `claude setup-token` on a machine with an active Claude subscription login (the host in this environment is already logged in via Claude Code, per the task brief, but I did not read or copy `~/.claude` credentials, and did not run `claude setup-token` myself — it prints a token to paste, and I have no way to know if that's welcome in this transcript).
2. Paste the resulting token into `secrets/claude_oauth_token.txt` (created empty by `scripts/dev-secrets-init.sh`; the file already exists with the right permissions after that script runs).
3. Restart the `llm-cli` service (`docker compose ... up -d --build llm-cli` or a full `make up`) — its self-check will log the CLI version and the container's healthcheck will report healthy once it can talk to Anthropic through `egress-proxy`.
4. To run the live corpus test: `cd api && LLMCLI_URL=http://127.0.0.1:<published-debug-port-if-any> LLMCLI_BEARER_TOKEN_PATH=../secrets/llmcli_bearer_token.txt go test -tags=claudecli ./internal/providers/llm/claudecli/... -run TestLiveGenerateNeverLeaksCanaryOrInvokesTools -v`. Because `llm-cli` has no published host port by design, this only works from inside the compose network (e.g. via `scripts/test-integration-toolbox.sh`'s pattern, or by temporarily publishing `8090` for the one-off test).
5. **Host-side fallback (now built, per the review fix):** if the CLI ever rejects token auth or a flag changes, build `api/cmd/llmcli` for Windows (`GOOS=windows GOARCH=amd64 go build -o llmcli.exe ./cmd/llmcli`, via the toolbox: `docker compose -f deploy/compose.tools.yml run --rm -e GOOS=windows -e GOARCH=amd64 --entrypoint go toolbox build -o /src/llmcli.exe ./api/cmd/llmcli`) and run it directly on the host with `LLMCLI_HOST_FALLBACK=1`, `LLMCLI_ADDR=127.0.0.1:8090`, `LLMCLI_BEARER_TOKEN_PATH` pointing at `secrets/llmcli_bearer_token.txt`, and `LLMCLI_MODEL`/`LLMCLI_SYSTEM_PROMPT` set the same as the container. It refuses to start on any non-loopback bind address and never reads `CLAUDE_OAUTH_TOKEN_PATH` — the spawned `claude` process uses the host user's own existing `claude login`/`claude setup-token` session directly; this process never opens that credential file. Point the worker/api at it with `LLMCLI_URL=http://host.docker.internal:8090` in `.env`.
