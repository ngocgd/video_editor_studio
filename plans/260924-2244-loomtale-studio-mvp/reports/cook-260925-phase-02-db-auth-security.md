## What was built

- **DB roles + tenancy schema.** `deploy/postgres/init-roles.sh` (docker-entrypoint-initdb.d) creates `loomtale_owner`/`loomtale_app` from Docker secrets on first boot; `db/migrations/20260925010000_db_roles.sql` grants the split (owner full DDL, app CRUD-by-default-privilege only, no DDL) and fails fast if the roles are missing. `20260925010100_core_tenancy.sql` adds `tenants`, `users`, `memberships`, `sessions`, `rate_limit_buckets`, `tenant_quotas`. `20260925010200_assets.sql`, `..._secrets.sql`, `..._ops.sql` (backup_runs), `..._audit.sql` (trigger-enforced immutable `audit_log`, refusing `goose down`) follow. UUIDv7 generated in Go (`api/internal/db/idconv`). `scripts/lint-tenant-queries.sh` fails CI if a query against a tenant table lacks `tenant_id = @tenant_id` (one documented exception via `lint-tenant-queries:allow`).
- **`tools/tenantctx`** — a separate Go module (`tools/go.mod`) with a `go/analysis` analyzer flagging `TenantID:`/`TenantId:` struct fields populated directly from a request's `Params`/`Body`; wired into `make lint`, which builds it and runs it against `api/...`. Deliberately syntactic (own-expression scope, not full data flow), documented as a scoped tradeoff; testdata covers a violation, a `tenantctx:allow`-annotated exception, and the safe (`tenant.FromCtx`-sourced) form.
- **Envelope encryption** (`api/internal/crypto/envelope`): AES-256-GCM, random per-record DEK wrapped by a KEK loaded from `/run/secrets/master_key` (32B base64, fails fast if absent/malformed), AAD = `tenant_id|kind|record_id`, `key_id` fingerprint for rotation. Property-style tests cover roundtrip, tamper detection (ciphertext, wrapped DEK, AAD mismatch), key-id mismatch, and per-call randomization. Not yet wired to an HTTP route (no secrets are created via the API in this phase — reused by phase 4/10 as planned).
- **Auth** (`api/internal/auth`, `authapi`): argon2id (m=64MiB,t=3,p=2) with PHC-string storage and rehash-on-login-if-outdated; session store (32B random token, only SHA-256 persisted); `__Host-lt_sess` cookie (HttpOnly, Secure, SameSite=Lax, 12h idle / 7d absolute); login/logout/me/switch-tenant/csrf handlers; login always issues a brand-new session (fixation defence) and switch-tenant rotates the existing session's token; a decoy-hash comparison on unknown-email login for timing-safe enumeration resistance.
- **CSRF** (`api/internal/csrf`): synchronizer token (hash stored on the session row), `X-CSRF-Token` header, Origin/Referer allowlist.
- **RBAC** (`api/internal/rbac`): reads `x-min-role` from the bundled OpenAPI spec (`gen.GetSwagger()`) into a `StrictMiddlewareFunc`; `BuildMinRoles` fails at startup if any operation lacks `x-min-role` (deny-by-default) or uses an unrecognised value.
- **Rate limiting**: a Postgres token bucket (`api/internal/ratelimit.DBBucket`, two statements per call — see deviation below) for login (5/min per IP+email, 20/hour per IP), and an in-memory token bucket for general flood defence (100/min per client IP, trusted-proxy-aware `httpx.RealIP` since chi's own `middleware.RealIP` is deprecated/spoofable).
- **Audit** (`api/internal/audit`): `Record` writes in the same transaction as the action it describes; `audit_log` has a `BEFORE UPDATE OR DELETE OR TRUNCATE` trigger that raises even for the table owner, and `loomtale_app` is revoked `UPDATE`/`DELETE`/`TRUNCATE` (INSERT/SELECT only); `GET /audit` is owner-only, cursor-paginated.
- **Storage** (`api/internal/storage`): `Internal` (in-network, full app creds, `GetObject`/Range, `PutObject`, internal presigned GET) and `Browser` (signs against `MINIO_PUBLIC_ENDPOINT`, presigned POST pinned to the exact key via `SetKey`, refuses any key under `t/{tenant}/render/`, ≤10 min TTL). `Finalize` does a HEAD (checksum, size) plus a 512B range-GET magic-byte sniff — never streams the full object — records `sha256` from an `x-amz-checksum-sha256` upload trailer when present, and validates the sniffed MIME against a per-kind allowlist (`document` trusts the presign-time declared MIME instead, since text/* has no magic bytes).
- **Request validation & error mapping**: `api/internal/validation` mounts a `kin-openapi`/`openapi3filter` validator built from the same bundled spec; `cmd/api/main.go` wires a problem+json `ResponseErrorHandlerFunc`/`RequestErrorHandlerFunc` that logs the real error server-side and returns a fixed, non-leaking title to the client.
- **Headers & logging**: `api/internal/secheaders` builds the exact enforcing CSP from the plan (no Report-Only), shared byte-for-byte with `deploy/caddy/Caddyfile` via `{$MEDIA_ORIGIN}`; the Caddyfile now uses `handle` blocks so `/api/*` responses carry only the API's own headers and static SPA responses carry only Caddy's (the previous `route`+global `header` shape stacked both sets on every response). `api/internal/obs/scrub` redacts secret-shaped log keys and strips capability-URL query strings (`X-Amz-Signature`, `X-Amz-Credential`, `upload_id`, `upload_protocol`); `api/internal/secretstr.String` redacts through `String()`/`GoString()`/`slog.LogValue()`/`MarshalJSON()`.
- **`loomtale create-owner`**: password read from stdin (TTY prompt or piped line), never argv; creates tenant + user + owner membership in one transaction.
- **Backups**: `deploy/backup/backup.sh` — `pg_dump -Fc`, age-encrypts (identity from the `backup_encryption_key` secret, recipient derived via `age-keygen -y`), uploads to `$BACKUP_TARGET` via `mc`; mirrors the object bucket locally, age-encrypts each object, uploads the encrypted mirror; retention prunes to 7 daily + 4 weekly dumps; records outcome in `backup_runs`. `deploy/docker/backup.Dockerfile` (Alpine 3.21, `postgresql17-client` to match the Postgres 17 server, `age`, `dcron`, `mc` copied from the same pinned `bitnamilegacy/minio-client` image `minio-init.sh` already uses). `/readyz` surfaces backup freshness (`api/internal/ops.BackupStatus`) as a `checks.backup` detail, never gating readiness itself.
- **Compose wiring**: new secrets (`postgres_owner_password`, `postgres_app_password`, `master_key`, `backup_encryption_key`, `backup_target_credentials`); a `migrate` one-shot service (same `api` image, `loomtale migrate up`, owner DSN) gating `api`/`worker` via `depends_on: service_completed_successfully`; Postgres gets `wal_compression=on` (`max_wal_size=2GB` already present); MinIO app credentials come from `.env` (`MINIO_APP_ACCESS_KEY`/`MINIO_APP_SECRET_KEY`, operator-provisioned once, never generated/printed at runtime) so `minio-init.sh` and the `api` service always agree — this is the fix for the phase 1 follow-up ("`/readyz` 503 until the MinIO app key is wired manually"). `scripts/dev-secrets-init.sh` generates every secret + matching `.env` value (including a real `age-keygen` identity) in one command for local dev.

## Perf numbers

- Login p95: 5 samples, 58–120ms (`curl -w %{time_total}`), well under the 400ms budget.
- Authenticated-read middleware overhead: `/healthz` (no session/tenant/RBAC) vs `/auth/me` (full chain incl. session lookup, membership lookup, RBAC) — both 2.6–3.2ms total request time; the marginal overhead is within measurement noise, not a distinguishable few ms, well under the ≤3ms budget.
- `EXPLAIN` on the assets cursor query (`tenant_id = $1 AND id > $2 ORDER BY id LIMIT $3`) shows `Index Scan using assets_tenant_id_id_idx`, confirmed for the audit query the same way (same `(tenant_id, id)` index shape).
- No API handler reads S3 streams except finalize's 512B range GET (`storage.Internal.Finalize`) — verified by code review of every `assetsapi` handler; `GetAsset`/`ListAssets` only ever call `Browser.PresignGet`/DB queries, never `GetObject`.

## Security checklist — verified mechanically

- [x] Cross-tenant access returns 404: `TestCrossTenantAssetAccessReturns404` (GET and finalize both), also manually verified via curl with two real tenants.
- [x] Tenant never read from request params: `tenantctx` analyzer runs clean against the real codebase in `make lint`.
- [x] Session fixation: login always creates a new session row (never reuses/updates an existing one); switch-tenant rotates token+CSRF hash on the existing row. Logout deletes the row (verified: `sessions` table empty after logout in manual testing).
- [x] CSRF enforced on every unsafe method; Origin checked: `TestCSRFRejectsRequestMissingToken`, plus manual curl (missing token → 403, bad Origin → 403 in `csrf` unit tests).
- [x] Secrets/capability URLs never in logs: `obs/scrub` and `secretstr` unit tests assert redaction through `slog` JSON output for both attribute-key matching and URL query-string stripping.
- [x] Browser presigned URLs ≤10min, exact key pinned (`SetKey`, not a prefix), `render/` refused (`ErrRenderPrefixForbidden`, unit-tested indirectly via `IsRenderKey`/`Key` tests and the presign handler's call site); internal URLs use step-scoped TTL and are never returned to a browser-facing response type.
- [x] Upload MIME sniffed server-side, declared type not trusted for finalize (except the documented `document`-kind exception, since text/* has no magic bytes — the declared MIME is still allowlist-checked at presign time): `sniff_test.go` plus `TestFinalizeWithoutUploadIsRejected`/manual finalize test showing the sniffed `image/png` overriding nothing incorrectly.
- [x] `audit_log`: UPDATE/DELETE/TRUNCATE raise even as table owner (`TestAuditLogRejectsUpdateAsOwnerRole`, `...DeleteAsOwnerRole`, plus a manual `psql` `UPDATE` as the bootstrap superuser); app role has INSERT/SELECT only (`TestAuditLogRejectsUpdateAsAppRole`, manual `psql` `permission denied` before even reaching the trigger); down migration refuses (`RAISE EXCEPTION` in `20260925010500_audit.sql`, code-reviewed — goose down was not actually invoked against a live DB since that would need a second migration to roll back first).
- [x] KEK absent → process refuses to start: `envelope.LoadKEK` returns an error `run()` propagates before the HTTP server ever listens; exercised implicitly every compose boot (the `master_key` secret is mounted, and removing it was not separately re-tested against a live container but is a direct, unconditional `os.ReadFile` failure path).
- [x] Enforcing CSP only, no Report-Only, `object-src 'none'`, Trusted Types: `secheaders` unit tests plus manual curl against both the API directly and through Caddy (`Content-Security-Policy` present once, byte-identical on both, no `Content-Security-Policy-Report-Only` header, `trusted-types default dompurify` and `require-trusted-types-for 'script'` present).
- [x] `loomtale_app` has no DDL rights: `TestAppRoleHasNoDDLRights` (`DROP TABLE users` → `permission denied`) plus manual `psql` confirmation.

## Deviations, with reasons

- **RT#8's browser-presign cache-flooring** (signing time floored to a 5-minute window for byte-identical URLs) is not implemented: `minio-go`'s `Client.Presign`/`PresignedGetObject` always sign at `time.Now()` with no caller-supplied clock, so achieving this needs a hand-rolled SigV4 signer. Documented in `storage/browser.go`'s doc comment as a follow-up rather than faked; it is a caching nicety, not a security or success-criteria item.
- **`ConsumeRateLimitToken` was redesigned from one CTE-chained statement into two statements** (`RefillRateLimitBucket` + `ConsumeRateLimitBucket`). The original single-statement design (an `INSERT ... ON CONFLICT ... RETURNING` CTE feeding a second write to the same table) is unsound in Postgres: sibling data-modifying CTEs targeting the same table execute against the same pre-statement MVCC snapshot and cannot see each other's writes (documented in Postgres's own "WITH Queries" chapter), which I hit as a real bug during manual testing (a brand-new bucket key's very first request was either always denied or errored "no rows in result set" depending on which broken variant I tried) before landing on the two-statement fix, which I verified live against the real stack (login succeeded, no false 429/500). This trades a small race window under heavy concurrent load on the exact same bucket key for correctness on every other case; acceptable for a login rate limiter.
- **`github.com/getkin/kin-openapi` bumped 0.142.0 → 0.144.0**: `govulncheck` found GO-2026-6112 (nil-pointer panic in `openapi3filter.ValidateRequest`, which `validation.Middleware` calls directly) reachable from this phase's own new code. Fixed by upgrading; `oapi-codegen` (the only other consumer) still builds and generates identically against the newer version.
- **`golang.org/x/term` and `github.com/oapi-codegen/runtime` added as new direct dependencies** (`create-owner`'s stdin password prompt; oapi-codegen v2.8.0's generated code needs a newer `runtime` than the `v1.1.1` the toolchain initially resolved — bumped to `v1.7.0`).
- **DB role passwords are real Docker secrets, not fixed/committed values.** I considered simplifying to a fixed dev-only password (to sidestep the two-places-to-set-the-same-value friction — `.env` for the app/migrate/worker/backup DSNs, `secrets/*.txt` for `init-roles.sh`) after worrying it would break CI, but confirmed `.github/workflows/ci.yml` never runs anything that applies these migrations (`test-integration` isn't a CI step, matching the pre-existing `workerpb` integration test's status), so there is no CI-compatibility reason to weaken it. Kept the real-secrets design since it is already implemented, tested end-to-end, and is the more correct shape for anything beyond pure local dev. `scripts/dev-secrets-init.sh` removes the operator friction for local dev by generating and syncing both places in one command.
- **`tools/tenantctx` lives in its own Go module** (`tools/go.mod`), not under `api/`, because the plan's file list places it at repo-root `tools/tenantctx/` while `api/` is its own module; `make lint` builds the analyzer binary from the `tools` module and runs it with its working directory inside `api/` (`cd api && ./bin/tenantctx ./...`) so package-pattern resolution uses `api`'s own module regardless of where the analyzer binary itself was built — the standard way to run a cross-module `go/analysis` tool.
- **Backup's cloud upload step (`mc mirror`/`mc cp` to `$BACKUP_TARGET`) was not run against a real Cloudflare R2/Backblaze B2 bucket.** No such account/credentials exist in this environment, and writing a target-credentials secrets file even with locally-generated placeholder values triggered this session's privacy-block hook, which requires interactive user approval via a tool (`AskUserQuestion`) that is unavailable to a subagent. What I did verify directly against the live containers: `pg_dump` against the real Postgres 17 server (fixed a client-version mismatch — Alpine 3.20's default `postgresql-client` resolves to v16, which refuses to dump a v17 server; switched to Alpine 3.21 + `postgresql17-client`), `age` encrypt/decrypt round-trip (byte-identical via `cmp`), and MinIO's S3 API via `mc` (exercised indirectly every stack boot through `minio-init.sh`, which the same pinned `mc` binary powers). I also found and fixed two container-stability bugs while getting this far: the `backup` service's `tmpfs`-mounted `/var/spool/cron` shadows the image-built `crontabs/` subdirectory at runtime (entrypoint now `mkdir -p`s it), and `crond -f` (foreground) fails `setpgid` as PID 1 under this container's capability restrictions (switched to `crond` daemonizing normally, backed by `/var/run` also on `tmpfs` for its pidfile, plus `exec tail -f /dev/null` to keep the container alive).
- **`age`'s dev-only encryption identity is generated correctly, but only after an initial mistake**: `scripts/dev-secrets-init.sh` originally generated `backup_encryption_key.txt` as base64 random bytes (matching the `master_key` pattern), which is not a valid age identity. Fixed to shell out to `age-keygen` (run once inside the already-built `backup` image, since `age-keygen` isn't on the host or in the toolbox), verified live.
- **Trailing `X-Frame-Options`/legacy header dropped** from the Caddyfile in favour of the CSP's `frame-ancestors 'none'`, which supersedes it in every modern browser; not in the plan's explicit header list, and keeping it would have meant the API and Caddy sending different header sets again (the API's `secheaders` package never set it).
- **`AuditEntry.metadata`** (optional `additionalProperties` object) is populated from the JSONB column when non-empty; not explicitly required by the spec but trivial and consistent with the schema.

## Unresolved questions

The full nightly-backup cloud upload path (`mc` to a real R2/B2 bucket, retention pruning against real object listings) is implemented and internally consistent but unverified end-to-end without live cloud credentials — should the controller supply a real (even short-lived, revocable) R2/B2 test bucket to close this out before merge, or defer full verification to phase 12's restore drill as the plan already anticipates?

PASSWORD` gets run against a live DB when the secret rotates) is out of scope here and not yet documented anywhere; worth a `docs/deployment-guide.md` note in a later phase.
3. `goose down` on the audit migration was verified by code review (the `DO $$ RAISE EXCEPTION ... $$` block) but not exercised against a live database, since doing so meaningfully would require first rolling back the later migrations that depend on `audit_log` existing.
