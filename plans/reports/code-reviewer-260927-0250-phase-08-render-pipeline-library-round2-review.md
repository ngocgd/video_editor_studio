## Findings

### High

**H1. With main merged, the e2e suite exceeds the per-user login bucket, and `writer-import-settings.spec.ts` fails deterministically.** `LoginPerUser` is `ratelimit.NewDBBucket(queries, 5, 5.0/60)` in `api/cmd/api/main.go:289`. It is keyed by IP plus email, allows a burst of 5 and refills one token every 12 s. Every spec signs in as `owner@loomtale.local` from the same IP. Main added `analytics.spec.ts`, and this branch adds `render-library.spec.ts`, which brings the suite to 7 spec files. The first five logins land within about 3 s. The sixth arrives about 10.6 s after the first and gets 429 (`19:30:24 POST /api/v1/auth/login 429`). This failed in 2 of 2 full runs, and the run without the render/library spec passed 6 of 6.

Merging this branch as it stands would turn main's Playwright red. The fix belongs in the e2e harness, not the limiter, because the limiter is a security control. For example, a Playwright `globalSetup` could sign in once and save `storageState`, which the specs would then reuse. Or the specs could share one login per worker. The harness is shared, so announce the change on the board.

### Medium

**M1. The worker's static ffmpeg has no NVENC (carried, re-confirmed).** The probe still answers `Unknown encoder 'h264_nvenc'`, so `encoder: auto` always resolves to libx264. The plan's risk table accepts the libx264 fallback, and the 60-min budget holds on CPU. However, the GPU check (`ENCODER=nvenc` records `h264_nvenc`) cannot pass until the GPU override uses an ffmpeg build that has NVENC.

**M2. Two concurrent starts can create two render runs (carried).** `RenderAPI.StartRender` (`api/internal/render/http.go:244`) checks `GetActiveRenderRun` and then calls `Freezer.Freeze`, with no lock and no unique constraint in between. There is a second window as well. `Freeze` inserts the manifest, enqueues the run and only then calls `SetManifestRun` (`freeze.go:111-122`). Until that last call, `GetActiveRenderRun` cannot see the new run. The web button is disabled while the mutation is pending, which lowers the chance of a double start but does not close the race. A per-episode/lang advisory lock would close both windows.

**M3. Step temp dirs on `/scratch` leak after a worker crash (carried).** `newTempDir` (`api/internal/render/inputs.go:22`) is removed only by the step's own deferred cleanup. Nothing sweeps `render-*` directories when the worker starts, and `renderscratch` is a named volume that survives restarts. The disk watermark covers `/scratch`, so a leak ends in refused enqueues rather than a full disk.

**M4. Migration ordering (carried, still awaiting the lead).** `20260927100000_renders.sql` sorts before main's `20260927400000` and `20260927500000`. `api/cmd/loomtale/migrate.go:53` calls `goose.UpContext` without `WithAllowMissing`, so a database that has already applied main's later versions refuses this one. Main already contains phase 7's lower versions merged after `20260927400000`, so this is a cross-branch decision.

**M5. A scene edit's debounced restart supersedes a run that already has the same manifest.** `Superseder.Restart` (`api/internal/render/supersede.go:120-160`) always freezes a new manifest and calls `SupersedeRun` on the active run. `GetActiveRenderRun` already returns the active manifest's `hash`, but `Restart` never compares it with the fresh manifest's hash. So an edit followed within 5 s by "Render episode" restarts that render with an identical manifest. So does any `scenes.Changed` event that does not change the render inputs. In-flight encodes are canceled and redone, and the page shows "Render restarted after edit" for no edit.

This also makes the render integration test sensitive to timing. In kill attempt 1, the run the test waited for "ended superseded" although the test made no edit after starting it. Suggested fix: when the new manifest's hash equals the active one's, skip the supersede. Skipping before inserting the manifest is better still.

### Low

- **L1–L4 (carried from round 1).** There are four items. A final render asset can be orphaned if the worker dies between the upload and `InsertRender`. `DeleteLibraryAssets` re-checks only takes and renders, not character references, voice presets, LoRAs or pinned manifests. `RemoveAllVersions` runs after the row delete and can drop a concurrent re-upload, which self-heals through the checksum check. `cmd/api` builds the `Freezer` without `Depth`, which is expected under the phase 9c pact.
- **L5.** The tests are thinner than the phase's Tests list: 3 scenes instead of 12, "1–2 transitions" instead of the exact pair, and no worker-kill test. The fixture's compose finishes in under 1 s, so a manual kill check needs a longer fixture.
- **L6 (main, owned by lane c).** `youtube-settings.spec.ts:22` is flaky because of a duplicate `h1` ("YouTube channels" in both the top bar and the view). It failed in 1 of 2 full runs here. Lane c has acknowledged it on the board.

### Checked and fine

- **Authorization.** `x-min-role` is viewer for every read. It is editor for the render settings PUT, `startRender`, the library settings PUT and both cleanup operations, which matches "Cleanup is owner/editor only".
- **Tenant isolation.** Every render, manifest and library query is scoped by `tenant_id`, and every join also matches `tenant_id`. `lint-tenant-queries` and tenantctx pass. Cleanup deletes objects only under the tenant's own prefix (`storage.IsTenantKey`), and `assets.storage_key` is unique, so one object is never shared by two rows.
- **Injection.**
  - Filtergraph values go through typed validators: expressions are single-quoted, with no quote, colon, backslash or bracket allowed. File and directory names use strict patterns. Filters and keys are allowlisted.
  - The subtitle font is limited to `^[A-Za-z0-9 ]{1,64}$` in both the OpenAPI spec and `Settings.Validate`.
  - ASS text escapes backslashes and braces. Frame sizes must be even and within range, and the encoder, fps, motion and subtitle mode are allowlisted.
- **SSRF and secrets.** Workers download inputs from asset rows through `storage.Internal` into 0700 temp dirs, and no URL comes from user input. No secrets appear in the diff.
- **Cleanup safety.** A manual cleanup must match the preview token. The audit write happens before the enqueue, and an unaudited cleanup never runs. The step re-lists candidates with every reference check in the same query, and the delete re-checks selected takes and renders.
- **Worker queue for the integration test.** The live worker serves `io` only when model steps are enabled, which the integration stack never enables. The integration run confirms this: 97 passed with 0 failed.
